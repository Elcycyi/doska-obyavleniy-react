# Доска объявлений на React

ДЗ7: та же доска, что делали на чистом JS, теперь на React + TypeScript,
с деплоем через GitHub Actions. Бэкенд прежний.

## Запуск

```
npm install
npm run dev
```

## Бэкенд

`https://inai-col1.fishrungames.com`

- `GET /ads` — список. Объявления приходят в поле `items`, поэтому в коде
  `setAdverts(data.items)`, а не `setAdverts(data)`.
- `POST /ads` — создать. Отправляется `multipart/form-data` с полями
  `title`, `description`, `price`, `image`.
- `image_url` приходит БЕЗ домена (`/uploads/abc.jpg`), домен приклеиваем сами
  в `AdCard.tsx`. Картинки может не быть вообще — тогда подставляется заглушка.

## ❗ Что сделать перед деплоем

**1. Имя репозитория.** В `vite.config.ts` стоит `base: '/doska-obyavleniy/'`.
Это имя папки на GitHub Pages. Назовёшь репозиторий иначе — поменяй и эту
строку, иначе сайт откроется белым: стили и скрипты будут искаться не там.

**2. Включить Pages правильно.** Settings → Pages → Source выбрать
**GitHub Actions**, НЕ «Deploy from a branch». Ветка `gh-pages` не нужна и не
создаётся — проект собирается из `main` прямо в Actions, как и требовалось.

**3. Положить проект в КОРЕНЬ репозитория.** `package.json` должен лежать
рядом с `.github`, а не внутри ещё одной папки — иначе Actions не найдёт его
и сборка упадёт на первом шаге.

После `git push` в `main` деплой запускается сам. Вкладка Actions покажет ход,
адрес сайта появится там же и в Settings → Pages.

## Разбор: что отвечать, если спросят

**Что такое `useEffect` и зачем пустой массив в конце?**
`useEffect` выполняет код ПОСЛЕ отрисовки компонента. Пустой массив `[]` значит
«только один раз, при открытии страницы». Без него загрузка запускалась бы на
каждой перерисовке: пришли данные → перерисовка → снова загрузка → вечный цикл.

**Почему `fetch` нельзя вызвать прямо в теле компонента?**
Тело компонента выполняется при каждой перерисовке. Запрос ушёл бы десятки раз.
Для таких «побочных действий» и существует `useEffect`.

**Зачем три состояния: `adverts`, `loading`, `error`?**
Чтобы показать пользователю, что происходит. Пока `loading` — надпись
«Загружаю», если `error` — красная плашка, иначе список карточек. Без этого
страница просто висит пустой, и непонятно, сломалось или грузится.

**Почему при отправке формы не ставим `Content-Type`?**
Потому что отправляется файл. Браузер сам проставит
`multipart/form-data` вместе с `boundary` — строкой-разделителем между полями.
Если написать заголовок руками, `boundary` потеряется и сервер не разберёт
запрос. Это самая частая ошибка в этом задании.

**Как список обновляется после добавления?**
`AdForm` получает через props функцию `onAdded`. После успешного POST он её
вызывает, а в `App` это `загрузить` — список перечитывается с сервера.
Так дочерний компонент сообщает родителю о событии, не зная о нём ничего.

**Зачем `response.ok` и `throw new Error`?**
`fetch` не считает ошибкой ответ 404 или 500 — он спокойно отдаёт результат.
Проверка `if (!response.ok) throw ...` превращает плохой ответ сервера
в настоящую ошибку, которую ловит `catch`.

**Что делает `key={advert.id}`?**
Даёт React понять, какая карточка какая при обновлении списка. Без него будет
предупреждение в консоли и лишние перерисовки.

**Зачем `finally`?**
`setLoading(false)` должен выполниться в любом случае — и когда всё хорошо,
и когда запрос упал. Иначе при ошибке надпись «Загружаю» останется навсегда.

## Структура

```
src/
  types/advert.ts          — описание объявления
  components/AdCard.tsx    — одна карточка, получает объявление через props
  components/AdForm.tsx    — форма подачи, POST с файлом
  App.tsx                  — загрузка списка, состояния, сборка страницы
.github/workflows/deploy.yml — сборка и публикация на Pages
```
